### 本轮源码核查事实：不是所有设备都通过蓝牙添加

这些是核查结论，**不是新获授权的产品开发任务**：

- `app/ProvisioningFlow.tsx:114` 调用 SDK 扫描。SDK `Provisioning.ts:272` 同时扫描 nRF54 BLE、ESP32 BLE、H7608 SoftAP；`ProvisioningFlow.tsx:183` 按 transport 区分连接提示。
- nRF54 配对固件与 ESP32/HC33 为蓝牙 BLE；H7608 为设备 Wi-Fi 热点。低功耗 `edgez-nrf54l15-fgh200m-sensor` 构建不提供 BLE，节点通过 HaLow 与网关通信。参见 `01_Software_Source/README.md:169`。
- 水阀、摄像头目前没有完成产品级添加路径，不能先认定为 BLE。
- 当前网页三条发现记录只模拟 BLE；SoftAP 的权限、热点连接与密码流程尚未展示。Agent 已纠正“搜索设备统一用蓝牙图标”的过度概括；不能把当前三条模拟记录解释为所有设备只支持蓝牙。后续补齐需先明确方案与相应授权。

## R37：弱化首页添加按钮

用户反馈右上角大黑圆加号“好大好丑”。用户随后明确：不能只有裸加号，必须有外框。最终采用36×36圆角细边框/卡片色内底、22px细线加号、44×44点击区；去掉大黑色实心圆，不缩小触控范围。最新纠正覆盖此前裸加号方案。

通用无线图标的后续讨论：Agent 提议用中心圆点与两侧弧线表示跨协议无线连接，由文字区分 BLE / Wi-Fi / HaLow。用户目前询问了是否有这种统一表示；尚未明确选择替换成该方案。**提议不能当成已批准并已实现的要求。**当前网页三个 BLE fixture 用蓝牙图标，SoftAP 分支待补齐。

## R38：账号页必须与其他二级页面对齐

用户：“为什么其他界面都是返回，而账号这边不是返回，账号界面的设计要和其他的设计对齐！”

账号从全屏弹层改为普通二级页面，使用和通知页相同的左侧“返回”、居中“账号”标题、状态栏与页面留白，不使用右上关闭叉。验证码/密码登录保留在账号页内切换；密码重置为下一级页面，返回账号。导航离开账号/重置页时取消未完成表单请求，清除临时密码/验证码，避免旧回调覆盖新页面。成功登录后留在账号页显示账号信息；返回回到设置六项菜单。服务能力限制未改变，网页不因此接通真实密码服务。
