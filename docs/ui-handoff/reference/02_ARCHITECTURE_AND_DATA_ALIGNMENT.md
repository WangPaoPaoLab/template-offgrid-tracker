## 一、 物理与射频通信三层拓扑（真实硬件现实）

系统整体由 **“手机 App ➔ 本地随身主控/网关 ➔ 远端长距离 HaLow Mesh 网络”** 三层构成：

```
┌────────────────────────────────────────────────────────┐
│  手机移动端 App (React Native / Expo / 本地 SQLite)    │
└──────────────────────────┬─────────────────────────────┘
                           │ 📱 手机直连网关通道 (双模支持):
                           │   - 模式 A（标配随身）: BLE 5.0 GATT (0xFFF0) 1对1绑定
                           │   - 模式 B（营地局域网）: 2.4GHz Wi-Fi SoftAP (WPA2 热点)
                           ▼
┌────────────────────────────────────────────────────────┐
│  本地随身主机 / 网关 (Local Master / Gateway)           │
│  - 主力方案 1: Nordic nRF54L15 + Quectel FGH200M (SPI) │
│  - 网关方案 2: Heltec HT-HC33 (ESP32-S3 + MM6108)     │
│  - 高性能网关 3: ESP32-P4 + MM8108 USB (Host)          │
│  - 职责: 充当硬件射频调制解调器 (Modem) 与多跳路由器   │
└──────────────────────────┬─────────────────────────────┘
                           │ 📡 空中物理层: IEEE 802.11ah Sub-1GHz (Wi-Fi HaLow)
                           │   - 频段限制: 严格受限于硬件，仅支持 868MHz (EU/GB) 与 915MHz (US/CA/AU等)
                           │   - 链路组网: 802.11s SAE/AMPE 对等链路 (Peer-Link)
                           │   - 多跳路由: BATMAN-IV (EtherType 0x4305) 动态无中心路由
                           ▼
       ┌───────────────────┴───────────────────┐
       ▼                                       ▼
┌──────────────────────────────┐ ┌──────────────────────────────┐
│ 远端低功耗传感器 (Sensors)   │ │ 远端随身对讲终端 (KT-002)     │
│ - 代表: KT-001 牛羊定位项圈  │ │ - 代表: 队友对讲手持机       │
│ - 芯片: nRF54L15 / ESP32-S3  │ │ - 芯片: nRF54 / ESP32-S3     │

│   无连接 Action Frame (EZPR) │ │ - 行为: 广播大厅、私聊加密信 │
│ - 功耗: 毫秒级发射即进深度休 │ │   封 (EZP v1)、OPUS 语音对讲 │

└──────────────────────────────┘ └──────────────────────────────┘
```

## 二、 手机与网关的两种连接方式及对 APP 设计的影响

系统中主控（如 Heltec HC33 / nRF54）支持与手机通过两种通道交互：

| 连接维度 | 方式 1：BLE 5.0 低功耗蓝牙透传 (标配随身) | 方式 2：2.4GHz Wi-Fi SoftAP 热点 (营地基站) |
| :--- | :--- | :--- |
| **底层通道** | 2.4GHz 蓝牙 GATT（Service `0xFFF0`） | 2.4GHz Wi-Fi WPA2 热点（SSID: `EZ-<MAC>`，密码: `edgez123`） |
| **拓扑关系** | **1 对 1 独占绑定**（一部手机绑定一个随身终端） | **1 对 多 局域网**（营地网关可同时接入多达 10 部手机） |
| **网络层级** | 手机与主控通过 Protobuf 二进制分片报文通信 | 手机接入 `10.80.x.x/27` 子网，直接通过 TCP/IP 与网关通信 |
| **手机端权限** | 依赖系统蓝牙权限（CoreBluetooth / Nearby Devices） | 依赖手机切换 Wi-Fi（部分系统会提示“该 Wi-Fi 无互联网”） |
| **功耗与保活** | 极低功耗，手机可后台常驻或定时唤醒拉取 | 手机端 Wi-Fi 功耗较高，锁屏容易被系统断开 Wi-Fi |
| **APP 交互定位** | **作为默认的消费级随身连接模式**（像 Apple Watch 一样无感） | **作为“营地基地台/车载大网关模式”**（多成员免配对接入） |

## 三、 硬件与 APP 的绝对职责边界（分工解耦）

1. **硬件做黑盒调制解调器（Radio Modem）**：
   - 所有的射频跳频、SPI 总线控制、802.11ah 帧调制、SAE 密码协商、BATMAN 多跳路由计算，全部由 MCU 固件自行闭环处理。
   - 手机 App 绝不参与、也不干预底层的 Mesh 路由计算或寄存器时序。
2. **APP 做指令下发与状态可视化中枢（UI & State Hub）**：
   - App 负责接收硬件抛上来的事件流（Protobuf 解包）；
   - 写入手机本地 SQLite 数据库；
   - 驱动界面渲染（地图轨迹、对讲气泡、电量与越界告警）；
   - 将用户的下行指令（发消息、寻物蜂鸣、修改信道）打包送入 BLE 通道。

## 四、 消费级 UI/UX 架构对齐准则 (iOS HIG + 米家范式)

1. **根导航彻底去社交化，精简为纯净双 Tab**：
   - **`[设备 (Devices)]`**：首页设备管理 Hub，呈现 2 列高密度设备卡片（KT-001 项圈、KT-002 对讲机）及一键配对入口。
   - **`[我的 (Profile)]`**：个人中心与系统设置，包含本地 NodeID、868/915MHz 射频参数、离线瓦片地图存储、语言切换。
2. **消息收敛于 KT-002 硬件详情内部**：
   - 移除独立的根“消息”Tab。通信与信道是对讲手持机硬件终端的核心能力，点击卡片下钻进入详情页。
   - **严格落地 iOS 推栈规范 (`hidesBottomBarWhenPushed`)**：进入设备详情页时，底部全局 Tab 栏自动平滑隐藏，顶部增设 `‹ 我的设备` 返回按钮。
3. **去品牌化，彻底回归用户中心**：
   - 坚决杜绝“OEM 乙方贴脸思维”：首页顶部为 `我的设备`；
   - 移除宣教式底栏 `为持续拓展的 KEEPTEEN 硬件生态而设计`；
   - 个人中心身份显示为 `本地节点 (主控终端)` 或自定义呼号，禁止使用 `KEEPTEEN 用户` 标签。
4. **确定性即时反馈闭环（三眼黄金法则）**：
   - **第 1 眼（连接状态）**：顶部呼吸点指示随身伴侣在线状态，网格胶囊显示当前在线节点数；
   - **第 2 眼（资产与安全）**：卡片直观呈现距离向量（`1.2km ↗ 围栏内正常`）、电量百分比；
   - **第 3 眼（操作反馈）**：消息发送包含状态流转（`正在发送 ➔ 已送达 ACK`），寻物蜂鸣等操作具备明确的成功下发回执。
