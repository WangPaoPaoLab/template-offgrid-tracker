# 正式网页版修改方案：按后端与设备能力对齐

核对日期：2026-11-14。用户已批准实施。2026-11-14 已在正式网页版实现产品 / 能力模型、演示适配器、状态与交互规格对齐；真实 App / SDK / 后端 / 固件缺口仍按能力清单联调，不将本次网页修改视为这些底层功能已完成。

依据：[后端与设备能力清单](BACKEND_CAPABILITIES.md)、[资源快照](BACKEND_RESOURCE_SNAPSHOT.json)及当前 `web_prototype/product-ui.js`、`UI_HANDOFF.md`。后端依据仍是清单中的固定提交与 SDK 0.1.35；本次没有重新审查远端最新提交、生产部署或真实硬件。

## 1. 产品与视觉约束

- 保留当前冷白 / 纯黑、紧凑双列卡片、灰色细线与局部橙色。
- 首页不恢复顶部重复连接列表；每张卡片只显示产品名称与最有用的一条状态。
- 保留“设备 / 我的”根导航。聊天属于独立产品，进入其卡片后管理频道、队友及会话。
- 项圈 / 耳标内保留“节点 / 地图 / 围栏”；水阀和摄像头继续只展示入口，雷达待后续定义。
- 图片、语音、已读、密码登录、电子围栏都是产品需求，不因现有接口缺口删除设计。交接必须把设计目标、现有能力和待开发接口分清。
- 网页继续承担可交互规格展示，不把本机模拟当成接通真实设备。演示开关和接口说明留在展示板外部，消费者页面使用自然的状态文案。

## 2. 当前实现与建议修改

| 范围 | 当前实现 / 缺口 | 建议修改 | 接口与协作要求 |
| --- | --- | --- | --- |
| 首页卡片 | 四个固定类型；连接只有 gateway / radio 两个布尔量 | 卡片绑定具体产品实例；可自定义名称；支持两个同类网关。短状态按产品呈现“未连接 / 等待上报 / 8 个节点”，而非用一种“已连接”概括全部链路 | 产品实例需明确类型、型号、固件和控制设备 ID；硬件平台 kind 不等于产品类型 |
| 连接状态 | 网页分别模拟两款产品的连接，但尚无 BLE ready、远端网络和云端状态 | 内页连接信息分别显示“手机与设备”“远端网络”“云服务”；首页只选一条主状态，具体优先级按产品能力决定 | BLE connected 与控制通道 ready 分开；云端可用不证明手机 BLE 已连，BLE 断开也不自动否定云端数据 |
| 网关节点 | 所有样本固定归于 gateway-01；无真实多网关选择与分页 | 进入产品仅加载其所属节点；增加首次加载、加载更多、部分加载失败、空网络、权限不足状态。按产品保留筛选和选中项 | 贯通 gatewayDeviceId；补 StoredDevice 映射与存储；明确云端、本地及无线 ID 映射。nodeNum 用十进制字符串 |
| 节点活跃与缓存 | recent() 固定 120 秒；断开 gateway 后列表直接变空 | 按型号的上报周期 / 容差判断数据新鲜度；无周期时显示最近上报时间，不武断标离线。已知节点失联后保留缓存，并显示“上次数据” | 聊天 SDK 的 120 秒 Beacon 窗口不能直接用于动物传感器；区分首次空网络与断链后的缓存 |
| 电压 | 有样本时统一显示电压；3.4 V 以下直接计入低电压 | 支持但未收到时显示“暂无数据”；明确不支持时不展示该指标；能力未知时不生成数值。告警阈值必须来自型号规则或真实告警，未确认前不使用统一 3.4 V 阈值 | 当前 FGH200M GPS_ONLY 构建关闭 ADC；SDK types 12 / 13 映射与 SQLite 迁移还需补齐；没有可靠百分比来源 |
| 信号与位置 | RSSI 固定标为“节点 → 网关”；时间与来源信息不足 | 基础层显示“HaLow 信号”和观测时间，详情说明哪个设备测得；不将扫描 BLE RSSI当作节点信号。位置显示来源、采集时间、有效性及最后已知位置 | 保留 reporter / peer / observedAt；坐标适配云端 [经度,纬度]，不能混用手机位置。无数据不补默认坐标 |
| 重命名 | 只改 localStorage 样本名称 | 保留编辑体验，区分本地别名与共享设备名称；显示保存中 / 保存失败，失败保留输入并可重试 | 云端 PATCH Device.name 或本地 saveProfileDevice；是否更改硬件广播名另定。改名不能改变设备身份 |
| 电子围栏 | 本地几何、启停、适用节点及确认提醒；没有执行端和同步状态 | 保存后区分“仅本机保存 / 待同步 / 同步失败 / 已确认生效”；显示实际监测方式，未确认前不声称设备离网独立执行。新围栏不预先显示正常 | 云端已有四形状判断，但 CRUD、enabled、网关作用域、告警确认权限及离网执行仍待闭环 |
| 围栏作用域 | deviceIds 为空在网页表达全部节点 | 从当前网关范围选节点，明确选择“此网关现有节点”还是包含未来加入节点；不能把空数组原样交给云端当作当前网关全部节点 | 当前云端空数组实际是 Profile 全部设备。显式 ID 集合仅覆盖当前集合；动态网关规则需补契约 |
| 地图 | 可交互示意底图；地图包管理仅说明文字 | 保留节点选择、定位时间、无定位与过期位置；另补离线包列表、下载中、取消、失败重试、删除确认的交互规格 | App 侧接原生地图与存储接口；轨迹查询与 iOS 能力需另验，不把示意底图当真实离线地图 |
| 聊天文字 | 网页用定时器模拟收发与回执 | 设计状态对应 Sending / Sent / Delivered / Retrying / Failed；断链保留消息和草稿，重试更新同一逻辑消息 | 接 SDK 与本地记录；SDK 接受发送不等于对端 ACK。公共频道只显示已发出，不显示全员送达 / 已读 |
| 语音消息 | 浏览器录音、文件试听和模拟发送 | 保留入口，细化权限、录制、取消、准备发送、传输、播放与重试；明确为语音消息，不增加实时通话承诺 | SDK 已有 startVoiceMessage / finishVoiceMessage / playVoiceMessage；App 入口及按媒体类型重试需接通。实际编码 / 容器按 SDK 与目标平台确认 |
| 图片与已读 | 网页本机图片可以预览；定时器模拟已读 | 保留完整设计和示例，但真实模式仅在协商支持后开放发送及展示已读。未收到独立已读回执，状态停留已送达 | 图片分片、接收、重组、存储与重试需补；readAt 需要独立协议及持久化。摄像头照片接口不能替代聊天附件链路 |
| 账号 | 邮箱验证码 / 密码均为本地演示 | 保留两种登录设计，补找回密码与账号服务错误流程。真实模式依据已启用认证方式开放；离线设备与聊天不强制先登录 | 基线启用邮箱 OTP，关闭 email-password；密码登录须服务、客户端和重置流程一起完成。不是短信登录 |
| 网络设置 | 每个目标使用默认 US / CH27，并初始化为 applied；应用结果由定时器决定 | 目标为具体产品实例；未读取到设备配置时显示未知，不用默认值假装当前值。普通页显示网络名称、密码、地区；信道 / 带宽放进高级设置，频率从合法组合派生 | 保存草稿、待接收、传输中、已应用、失败、过期分开。只有可靠设备确认 / 可用读回才能显示已应用；不同传输路径确认机制须联调 |
| 能力与设置范围 | 未按具体固件构建限制设置 | 统一从能力模型决定字段、允许值和写入入口；已知不支持不展示，未知能力不默认支持。未确认写入 / 读回的发射功率、跳数不做可编辑控制 | GPS_ONLY 构建仅允许 samplingIntervalMs=60000、blockSamplingCount=0。产品未确认前不新增通用采样设置 |
| 诊断 | 关于页只有两条模拟连接状态 | 保留消费者简洁入口，诊断内展示型号、固件版本、控制通道状态、最近错误与重连入口；升级能力另立流程 | OTA 如纳入范围，必须显示进度、失败、重连与版本核对，不能用立即成功开关代替 |

## 3. 页面应表达的状态

| 情况 | 首页 | 项圈 / 耳标内页 | 聊天内页 |
| --- | --- | --- | --- |
| 从未添加 / 未连接 | 产品入口与添加按钮；未连接 | 配对指引；不伪造节点数与指标 | 连接指引；可用本地历史不依赖登录 |
| 主控就绪、尚无远端 | 主控状态清楚，等待远端数据 | 等待节点入网 / 上报，不预填样本 | 频道可进入，队友为空，状态依据真实扫描 / 监听能力 |
| 活跃网络 | 产品各自的一条简短状态 | 当前网关节点、各观测时间与数据有效性 | 已发现队友，按真实能力发送文字 / 语音 / 图片 |
| 主控断链 | 不覆盖其他产品状态 | 保留已知节点和上次数据，标明更新时间；云端新数据另行判断 | 保留记录与草稿；按产品策略禁发或明确排队，不能悄悄丢弃 |
| 云端离线 / 会话失效 | 本地产品仍可用 | 本地数据与云缓存各有来源和时间 | 离线聊天不被账号失败连带禁用 |
| 权限不足 / 部分失败 | 必要时给出产品级反馈 | 区分无权限、没有节点、加载失败，支持重试 | 区分无队友、设备断链与发送失败 |

## 4. 前端适配结构建议

现有 `product-ui.js` 同时负责样本、页面、校验和模拟传输。建议按职责拆分，保持无构建静态网页也能打开：

1. 产品与能力模型：ProductInstance、Node、Observation、ConnectionState。规定空值、未知、不支持和过期的处理。
2. 适配层：产品列表 / 节点 / 观测 / 改名 / 配置 / 围栏 / 聊天 / 账号 / 地图各自提供明确的调用输入和状态回报。方法名为前端内部约定，不冒充已有 REST API。
3. 演示适配器：保留样本与可复现的成功 / 失败场景，经同一套模型驱动页面，不在渲染函数里直接决定请求结果。
4. 页面层：只根据数据、能力与操作状态展示；不能自行把一次定时器结束、HTTP 入队成功或本地保存变成设备已生效。
5. App 接入：由 App 同事将同一份 UI 契约映射到 SDK、SQLite 和云端服务；HTML 不引入必须在 React Native 中运行的 BLE / 原生地图模块。

## 5. 射频与语言的完整性

基线默认注册地区完整为 AU、CA、EU、GB、IN、JP、KR、NZ、US，共 188 条记录；当前无 CN。保持完整驱动目录，不因高级选项折叠而删除记录；设备实际可选项按固件构建、硬件 SKU 及经确认的区域许可取交集。本文没有核验现行法规，也不把驱动支持视为产品认证。

12 种离线语言继续保留。新增状态和错误文案同步进入全部语言源文件与生成脚本，不与无线地区一对一绑定。

## 6. 交接文档需要纠正的内容

- `UI_HANDOFF.md` 目前关于语音的“SDK 要求原始 Opus 数据”描述与后端清单冲突。以已核查 SDK 为准：Android API 29+ 为 Ogg/Opus、旧版本为 3GP/AMR-NB；浏览器文件不能不经适配就视为兼容。后续实现时同步改正旧文档。
- 早期架构文档中的统一电量百分比、寻物蜂鸣、固定上报周期及实时语音描述，不能作为本轮已实现功能的依据。保留愿景时需明确依赖及型号条件。
- 界面截图、模型测试通过仅证明展示板，不证明账号服务、离网围栏或媒体互通已经可用。

## 7. 建议实施批次与验收

第一批：产品实例 / 多网关模型、能力模型、连接分层、缓存与新鲜度、节点字段语义。此批不重画视觉，优先消除前后端错误对应。

第二批：配置完整状态、围栏作用域和同步状态、重命名反馈、账号与地图的完整流程；演示模型覆盖接口失败与未知能力。

第三批：以接口契约对接文字与 SDK 语音；并行推进图片、独立已读、密码登录所需的 SDK / 账号服务工作。保留消费者设计，不把待开发功能标成当前已支持。

至少验收：两个同类网关节点不串组、节点改名后 ID 不变、BLE 断开但云端仍有更新、云端离线但 BLE 可用、节点按不同周期休眠、无 ADC 构建、缺失位置、旧数据恢复、无权限与分页失败、切换产品时未完成请求不串回调、配置失败保留上次确认值、围栏跨网关范围、媒体断链与重试、送达未读与独立已读、账号失败不阻断离线功能。每项结论区分网页模型验收和后续真实接口 / 硬件验收。
